# ClipVault 部署指南

## 方案对比

| | 一键脚本（推荐） | Docker |
|---|---|---|
| 适合 | 干净的 Ubuntu 云服务器 | 熟悉容器 / 想快速起本地环境 |
| 组成 | systemd + Nginx | docker compose |

## 方案一：一键脚本（Ubuntu 22.04）

### 1. 购买并连接服务器

以阿里云/腾讯云轻量服务器为例，镜像选 **Ubuntu 22.04**，安全组/防火墙放行 **22、80** 端口。

### 2. 上传代码

```bash
# 本机执行（Windows 用 scp 需要 OpenSSH 客户端，或用 WinSCP 图形化拖拽）
scp -r clipvault user@服务器IP:/tmp/
```

### 3. 执行部署

```bash
ssh user@服务器IP
cd /tmp/clipvault
sudo bash deploy/deploy.sh
```

脚本会自动完成：
1. 安装 python3 / venv / nginx
2. 代码部署到 `/opt/clipvault` 并创建虚拟环境
3. 注册 systemd 服务（开机自启、崩溃自动拉起）
4. 配置 Nginx 反向代理（80 → 8000）

### 4. 验证

```bash
systemctl status clipvault        # active (running)
curl http://127.0.0.1:8000/api/health   # {"status":"ok",...}
```

浏览器访问 `http://服务器IP` 即可。

## 方案二：Docker

```bash
cd clipvault
BASE_URL=http://服务器IP docker compose up -d --build
# 8000 端口直接暴露，前面可自行加 Nginx 或 SLB
```

数据持久化：`./data/uploads`（文件）与 `./data/db`（SQLite）。

## 进阶：配置 HTTPS（启用端到端加密的前提）

Web Crypto API 只在安全上下文可用。公网 IP 无域名时：

### 情形 A：有域名（推荐，Let's Encrypt 免费证书）

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your.domain.com
# 自动配置续期，https://your.domain.com 即为安全上下文
```

### 情形 B：只有公网 IP（自签名证书，演示可用）

```bash
sudo openssl req -x509 -nodes -days 365 \
  -newkey rsa:2048 \
  -keyout /etc/ssl/clipvault.key \
  -out /etc/ssl/clipvault.crt \
  -subj "/CN=服务器IP"
```

Nginx 增加 server 块：

```nginx
server {
    listen 443 ssl;
    server_name _;
    ssl_certificate /etc/ssl/clipvault.crt;
    ssl_certificate_key /etc/ssl/clipvault.key;
    client_max_body_size 100m;
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

> 自签证书浏览器会警告，点「高级 → 继续访问」一次即可（演示场景完全够用）。

## 运维速查

```bash
systemctl restart clipvault                 # 重启服务
journalctl -u clipvault -f --since today    # 看日志
sqlite3 /opt/clipvault/clipvault.db "select code, view_count, max_views from shares;"   # 查库
du -sh /opt/clipvault/uploads               # 文件占用
```

## 常见问题

**Q：访问不了 / 一直转圈？**
1. 云厂商安全组是否放行 80/443 端口（最常见的坑）
2. 服务器内 `sudo ufw status` 确认系统防火墙
3. `systemctl status clipvault` 看服务是否在跑

**Q：上传文件 413？**
Nginx `client_max_body_size` 默认 1MB，本项目配置已设为 100m，若自己改过 Nginx 请同步调整。

**Q：端到端加密按钮提示环境不支持？**
加密功能需要 HTTPS（或 localhost 访问）。按上文配置证书即可。
